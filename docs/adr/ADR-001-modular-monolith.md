# ADR-001：模块化单体架构

- 日期：2026-08-09
- 状态：已接受

## 背景
第一版需要持续增加业务模块（提示词、Skill、专家包、MCP 目录），但不能引入微服务复杂度。

## 决策
采用编译期模块化单体：根 Go module 下 `internal/modules`，每个业务模块实现 `Module` 接口并注册迁移、路由、MCP 工具、健康检查；前端使用相同模块 ID 的静态注册表。模块可通过 `AIHUB_MODULES` 启停，但新增模块需要写代码并重新构建。

## 后果
- 优点：单一部署单元、共享事务/存储、开发简单。
- 代价：不支持运行时插件上传；模块间通过共享 `Deps` 与接口协作。
